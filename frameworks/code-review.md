# Framework — Code Review

Revisão é responsabilidade do **code-reviewer** (agente core), não só do humano.

## Quando acionar
- Antes de Sprint Review.
- Análise de commits.
- Revisão de PR.

## O que o code-reviewer avalia
- Qualidade, performance, manutenibilidade.
- Python, SQL, TypeScript.
- Ausência de hardcodes e segredos.

## Fluxo
1. PR aberto → code-reviewer comenta (não mergeia).
2. Autor ajusta.
3. Kai dá DoD; Gabriel aprova deploy.

## Fronteira
code-reviewer não decide arquitetura (isso é Bruno/Marco/Sofia). Aponta risco, não impõe.
